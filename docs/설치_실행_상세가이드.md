# Pinky Pro + Gazebo Harmonic + Multi Room 설치 및 실행 가이드

> **기준 환경:** Ubuntu 24.04 / ROS 2 Jazzy 설치 완료 / Gazebo Harmonic (Gazebo Sim 8)  
> **워크스페이스:** `~/pinky_ws`  
> **목적:** Pinky Pro 시뮬레이션 → Multi Room 월드 → SLAM Toolbox 지도 생성 → Nav2 자율주행  
> **주의:** 이 문서는 실제 진행했던 문제와 수정 사항을 포함한다. GitHub 저장소 업데이트에 따라 파일 구조나 실행 방식이 달라질 수 있다.

## 0. 사용 저장소

- Pinky Pro: https://github.com/pinklab-art/pinky_pro
- Multi Room: https://github.com/makerspet/oomwoo_gazebo
- (참고용, 문제 발생) Gazebo Classic 데이터셋: https://github.com/mlherd/Dataset-of-Gazebo-Worlds-Models-and-Maps
- (참고용, 주행 문제 발생) World Collection: https://github.com/mertgulerx/world-collection

## 1. 기본 환경 및 선택적 Gazebo 설치

ROS 2 Jazzy는 이미 설치되어 있다고 가정한다.

```bash
source /opt/ros/jazzy/setup.bash
echo $ROS_DISTRO    # jazzy
```

### Gazebo 설치: 설치되지 않은 사람만

```bash
gz sim --help
```

정상 실행된다면 아래 설치는 **생략**한다. `gz` 명령이 없다면:

```bash
sudo apt update
sudo apt install -y ros-jazzy-ros-gz
```

기본 도구 및 SLAM/Nav2 관련 패키지:

```bash
sudo apt install -y \
  git python3-colcon-common-extensions python3-rosdep \
  ros-jazzy-teleop-twist-keyboard \
  ros-jazzy-slam-toolbox \
  ros-jazzy-navigation2 ros-jazzy-nav2-bringup \
  ros-jazzy-nav2-simple-commander
```

`rosdep`를 처음 사용하는 경우만:

```bash
sudo rosdep init
rosdep update
```

## 2. Pinky Pro 다운로드 및 빌드

새 터미널에서도 매번 `source ~/pinky_ws/install/setup.bash`를 실행한다. 한 워크스페이스만 사용하는 경우 `.bashrc`에 등록할 수도 있다.

## 4. Pinky Pro Launch 수정: 외부 월드 + 초기 위치 인자

기본 Pinky Gazebo 설정의 스폰 좌표가 고정되어 있었으므로 아래 두 파일을 수정한다. 수정 전 백업 권장:

```bash
cp ~/pinky_ws/src/pinky_pro/pinky_gz_sim/launch/launch_sim.launch.xml \
   ~/pinky_ws/src/pinky_pro/pinky_gz_sim/launch/launch_sim.launch.xml.bak
cp ~/pinky_ws/src/pinky_pro/pinky_bringup/launch/bringup_sim.launch.xml \
   ~/pinky_ws/src/pinky_pro/pinky_bringup/launch/bringup_sim.launch.xml.bak
```

기본 스폰 좌표는 실제 Multi Room에서 확인한 위치를 사용한다.

| 인자 | 기본값 | 의미 |
|---|---:|---|
| `x` | -0.971979 | Gazebo 월드 X |
| `y` | 0.028805 | Gazebo 월드 Y |
| `z` | 0.1 | 스폰 높이 |
| `yaw` | -3.130950 | 스폰 방향 (라디안) |

### 4-1. `pinky_gz_sim/launch/launch_sim.launch.xml` 전체

```xml
<?xml version="1.0"?>
<launch>
    <arg name="namespace" default=""/>
    <arg name="robot_name" default="$(var namespace)pinky"/>
    <arg name="cam_tilt_deg" default="0"/>

    <arg name="world_name" default="pinky_factory.world"/>
    <arg name="world" default="$(find-pkg-share pinky_gz_sim)/worlds/$(var world_name)"/>

    <arg name="x" default="-0.971979"/>
    <arg name="y" default="0.028805"/>
    <arg name="z" default="0.1"/>
    <arg name="yaw" default="-3.130950"/>

    <arg name="bridge_params" default="$(find-pkg-share pinky_gz_sim)/params/pinky_bridge.yaml"/>

    <set_env name="GZ_SIM_RESOURCE_PATH"
             value="$(find-pkg-share pinky_description)/../:$(find-pkg-share pinky_gz_sim)/models:$(env HOME)/.gazebo/models"/>

    <include file="$(find-pkg-share ros_gz_sim)/launch/gz_sim.launch.py">
        <arg name="gz_args" value="-r -s -v4 $(var world)"/>
        <arg name="on_exit_shutdown" value="true"/>
    </include>

    <include file="$(find-pkg-share ros_gz_sim)/launch/gz_sim.launch.py">
        <arg name="gz_args" value="-g -v4"/>
    </include>

    <include file="$(find-pkg-share pinky_description)/launch/upload_robot.launch.py">
        <arg name="namespace" value="$(var namespace)"/>
        <arg name="use_sim_time" value="True"/>
        <arg name="is_sim" value="True"/>
        <arg name="cam_tilt_deg" value="$(var cam_tilt_deg)"/>
    </include>

    <node pkg="ros_gz_sim" exec="create" name="create" output="screen"
          args="-name $(var robot_name) -topic $(var namespace)/robot_description -x $(var x) -y $(var y) -z $(var z) -Y $(var yaw)">
        <param name="use_sim_time" value="True"/>
    </node>

    <node pkg="ros_gz_bridge" exec="parameter_bridge" name="parameter_bridge"
          output="screen" args="--ros-args -p config_file:=$(var bridge_params)"/>
    <node pkg="ros_gz_image" exec="image_bridge" name="image_bridge"
          output="screen" args="/camera/image_raw"/>
    <node pkg="ros_gz_image" exec="image_bridge" name="image_bridge"
          output="screen" args="/camera"/>
</launch>
```

### 4-2. `pinky_bringup/launch/bringup_sim.launch.xml` 전체

아래는 기존 MuJoCo 실행을 유지하면서 Gazebo 외부 월드 및 스폰 인자를 전달하는 구성이다. **`world`가 비어 있으면 기본 Pinky 월드 경로를 사용**한다.

```xml
<?xml version="1.0"?>
<launch>
    <arg name="sim" default="mujoco"/>
    <arg name="world_name" default="pinky_factory.world"/>
    <arg name="cam_tilt_deg" default="8"/>
    <arg name="world" default=""/>

    <arg name="x" default="-0.971979"/>
    <arg name="y" default="0.028805"/>
    <arg name="z" default="0.1"/>
    <arg name="yaw" default="-3.130950"/>

    <arg name="use_gpu" default="false"/>
    <arg name="viewer" default="true"/>
    <arg name="camera" default="true"/>
    <arg name="namespace" default=""/>

    <let name="use_mujoco" value="$(eval '&quot;$(var sim)&quot; == &quot;mujoco&quot;')"/>
    <let name="use_gazebo" value="$(eval '&quot;$(var sim)&quot; in (&quot;gz&quot;, &quot;gazebo&quot;)')"/>
    <log message="[pinky_bringup] simulator: $(var sim)"/>

    <include file="$(find-pkg-share pinky_mujoco)/launch/launch_sim.launch.py" if="$(var use_mujoco)">
        <arg name="use_gpu" value="$(var use_gpu)"/>
        <arg name="viewer" value="$(var viewer)"/>
        <arg name="camera" value="$(var camera)"/>
        <arg name="world_name" value="$(var world_name)"/>
        <arg name="world" value="$(var world)"/>
        <arg name="cam_tilt_deg" value="$(var cam_tilt_deg)"/>
    </include>

    <include file="$(find-pkg-share pinky_gz_sim)/launch/launch_sim.launch.xml" if="$(var use_gazebo)">
        <arg name="world_name" value="$(var world_name)"/>
        <arg name="world" value="$(eval '&quot;$(var world)&quot; if &quot;$(var world)&quot; else &quot;$(find-pkg-share pinky_gz_sim)/worlds/$(var world_name)&quot;')"/>
        <arg name="cam_tilt_deg" value="$(var cam_tilt_deg)"/>
        <arg name="namespace" value="$(var namespace)"/>
        <arg name="x" value="$(var x)"/>
        <arg name="y" value="$(var y)"/>
        <arg name="z" value="$(var z)"/>
        <arg name="yaw" value="$(var yaw)"/>
    </include>
</launch>
```

> **주의:** XML 선언 `<?xml ... ?>` 위에 빈 줄이 있으면 `XML or text declaration not at start of entity` 오류가 발생한다. 코드 블록의 시작에 빈 줄을 복사하지 말 것. 일부 ROS Launch 버전에서 `$(eval ...)` 인자 평가에 문제가 생기면 오류 로그를 기준으로 분기식을 점검해야 한다.

### 4-3. 빌드·문법·인자 확인

```bash
cd ~/pinky_ws
python3 - <<'PY'
import xml.etree.ElementTree as ET
from pathlib import Path
for p in [
    Path.home()/"pinky_ws/src/pinky_pro/pinky_gz_sim/launch/launch_sim.launch.xml",
    Path.home()/"pinky_ws/src/pinky_pro/pinky_bringup/launch/bringup_sim.launch.xml",
]:
    ET.parse(p)
    print("XML OK:", p)
PY

colcon build --symlink-install --packages-select pinky_gz_sim pinky_bringup
source install/setup.bash
ros2 launch pinky_bringup bringup_sim.launch.xml --show-args
```

### SLAM 지도 저장

SLAM이 실행 중인 상태에서:

```bash
mkdir -p ~/pinky_ws/maps
ros2 run nav2_map_server map_saver_cli -f ~/pinky_ws/maps/multi_room
```

생성되는 파일:

```text
~/pinky_ws/maps/multi_room.yaml
~/pinky_ws/maps/multi_room.pgm
```

**지도 저장 오류 실제 원인:** `ROS_DOMAIN_ID`가 서로 달랐다. 모든 ROS 터미널에서 일치시키고 관련 노드를 다시 실행한다.

```bash
echo $ROS_DOMAIN_ID
export ROS_DOMAIN_ID=0
```

동일 도메인에서도 저장이 지연된다면:

```bash
ros2 run nav2_map_server map_saver_cli \
  -f ~/pinky_ws/maps/multi_room \
  --ros-args -p save_map_timeout:=10.0
```

## 7. 저장한 지도에서 Nav2 자율주행

SLAM Toolbox 및 SLAM용 RViz를 종료하고 **Gazebo는 유지**한다.

**터미널 3 — Nav2**

```bash
source ~/pinky_ws/install/setup.bash
ros2 launch pinky_navigation gz_bringup_launch.xml \
  map:=$HOME/pinky_ws/maps/multi_room.yaml
```

**터미널 4 — Nav2 RViz**

```bash
source ~/pinky_ws/install/setup.bash
ros2 launch pinky_navigation gz_nav2_view.launch.xml
```

RViz에서 `2D Pose Estimate`로 초기 추정 위치를 지정하고, `Nav2 Goal`로 목적지를 지정한다.

```bash
ros2 lifecycle get /bt_navigator
```

활성화 상태는 `active [3]`이다.

> Gazebo의 실제 스폰 좌표와 AMCL의 초기 `map` 좌표는 별개다. 파일의 AMCL 예제 설정은 `set_initial_pose: true`, `initial_pose: [0, 0, 0]`이었다. `2D Pose Estimate`로 맵에 맞게 설정해야 한다.

## 8. 자주 쓰는 명령어

### 위치 확인

```bash
# Gazebo 월드 기준
 gz model -m pinky -p

# Odometry 기준
ros2 topic echo /odom --once

# AMCL의 맵 기준 추정 위치 (AMCL 실행 시)
ros2 topic echo /amcl_pose --once
```

### Costmap 초기화

```bash
ros2 service call /global_costmap/clear_entirely_global_costmap \
  nav2_msgs/srv/ClearEntireCostmap "{}"

ros2 service call /local_costmap/clear_entirely_local_costmap \
  nav2_msgs/srv/ClearEntireCostmap "{}"

ros2 service list | grep clear
```

### 사용한 Nav2 Costmap 주요 설정값

기존에 확인한 `nav2_params.yaml` 기준:

| 항목 | Local | Global |
|---|---:|---:|
| `inflation_radius` | 0.15m | 0.15m |
| `cost_scaling_factor` | 3.0 | 3.0 |
| `resolution` | 0.05m | 0.05m |
| `footprint` | 0.12m × 0.12m | 0.12m × 0.12m |

기타: `xy_goal_tolerance=0.25m`, `yaw_goal_tolerance=0.25rad`. 주석 처리된 `robot_radius: 0.22`는 적용되지 않는다.

실행 중 설정 확인:

```bash
ros2 param get /local_costmap/local_costmap inflation_layer.inflation_radius
ros2 param get /global_costmap/global_costmap inflation_layer.inflation_radius
```

## 9. 발생했던 주요 오류 및 해결 내역

| 증상/오류 | 원인 및 대응 |
|---|---|
| `Package 'pinky_bringup' not found` | 빌드 후 `source ~/pinky_ws/install/setup.bash` 누락 |
| Gazebo GUI는 켜지는데 로봇이 안 보임 | `gz model --list`, `gz model -m pinky -p`로 확인. 바닥 없는 월드에서 Z가 계속 감소 |
| Gazebo에서 `pinky`만 보임 | 월드 파일 전달 누락으로 바닥이 없는 기본 월드가 실행된 경우가 있었음 |
| `gz_args` 실제 프로세스에 경로가 없음 | `ps aux | grep '[g]z sim'`으로 인자 확인; `world` 전달 수정 |
| `/cmd_vel`은 정상인데 주행 안 됨 | 키보드 조종 입력키 확인. `teleop_twist_keyboard`의 `q/z/w/x/e/c`는 속도 설정키 |
| 바퀴는 도는데 본체가 안 움직임 | 외부 SC1 월드에서 바닥 Collision 또는 물리 접촉 문제 발생; Multi Room 사용 권장 |
| `launch configuration 'x' does not exist` | 상위 Launch의 `<arg name="x" .../>` 등 선언 누락 |
| `XML or text declaration not at start of entity` | `<?xml ... ?>` 위 공백/빈 줄/문자 제거 |
| `Failed to spin map subscription` | 당시 원인은 ROS_DOMAIN_ID 불일치. 동일 도메인으로 재실행 |
| Nav2 목표에 도착 전 `Goal succeeded` | AMCL 위치 추정과 Goal Tolerance 확인 필요 |
| RViz timestamp/TF cache 경고 | Gazebo 시간 재시작 후 기존 TF 캐시와 불일치 가능. Gazebo → Nav2 → RViz 순서로 재실행 |
| `gz_frame_id` SDF 경고 | 카메라/IMU/LiDAR 설정 관련 경고. 주행/SLAM 자체는 가능했음 |

### Gazebo 실행 상태 점검

```bash
gz model --list
gz model -m pinky -p
ps aux | grep '[g]z sim'
```

### ROS_DOMAIN_ID 관련

```bash
echo $ROS_DOMAIN_ID
ros2 topic list
```

`ros2 daemon stop` / `ros2 daemon start`는 ROS 그래프 발견용 데몬 관련 명령이지 TF 캐시를 직접 초기화하는 방법은 아니다.

## 10. 다른 외부 월드에서 겪은 문제 (참고)

### Classic 데이터셋의 Small House

Gazebo Classic 시절 모델을 Harmonic에서 불러오며 `file://models/...` 경로 오류, TurtleBot3 모델 누락, `invalid inertia` 등의 문제가 발생했다. URI 수정, Static 설정, 임시 관성 텐서 추가 등을 시도했지만 정상 실행을 확인하지 못했다. 본 가이드의 기본 설치에서는 제외한다.

### World Collection의 `SC1_square_loop`

월드 자체는 정상 실행했지만 Pinky 바퀴가 바닥에 일부 파묻히고 속도 명령에도 본체 이동이 거의 없었다. Physics 스텝과 바닥 Collision을 조정해도 해결을 확인하지 못했다. 이 이유로 Multi Room으로 전환했다.

## 11. 최종 실행 순서 요약

```bash
# [터미널 1] Gazebo + Pinky Pro
source ~/pinky_ws/install/setup.bash
ros2 launch pinky_bringup bringup_sim.launch.xml \
  sim:=gz world:=$HOME/pinky_ws/oomwoo_gazebo/worlds/multi_room.sdf

# [터미널 2] 키보드 조종
ros2 run teleop_twist_keyboard teleop_twist_keyboard

# [터미널 3] SLAM
ros2 launch pinky_navigation gz_map_building.launch.xml

# [터미널 4] RViz (SLAM)
ros2 launch pinky_navigation gz_map_view.launch.xml

# [별도 터미널] 지도 저장
ros2 run nav2_map_server map_saver_cli -f ~/pinky_ws/maps/multi_room

# SLAM과 해당 RViz 종료 후 [터미널 3] Nav2
ros2 launch pinky_navigation gz_bringup_launch.xml \
  map:=$HOME/pinky_ws/maps/multi_room.yaml

# [터미널 4] RViz (Nav2)
ros2 launch pinky_navigation gz_nav2_view.launch.xml
```

**주의:** 위 명령은 한 번에 모두 실행하는 스크립트가 아니다. 각 단계에 맞춰 **서로 다른 터미널**에서 실행하고 SLAM과 Nav2를 전환한다. 각 터미널은 동일한 `ROS_DOMAIN_ID`와 워크스페이스 설정을 사용한다.
